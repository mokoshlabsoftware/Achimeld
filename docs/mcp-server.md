# Local editor MCP

The initialize instructions point agents to the embedded [achievement-authoring guide](agent-achievement-authoring.md), available through `resources/list` and `resources/read` at `achimeld://guides/achievement-authoring`. It distinguishes record names from optional icon lettering, requires clarification of ambiguous text, and treats requests for styles or icon styles as native Achimeld work by default. Ordinary image generation belongs to the agent's tools, not Achimeld. This is agent guidance, not semantic enforcement of natural-language intent by the tool dispatcher.

The [MCP guidelines](mcp-guidelines.md) define the expected minimized-window, handshake, reconnect, health, and error behavior. The current implementation and live qualification are tracked separately in the [MCP audit](security/mcp-audit.md).

Build and Run also recovers connectors from older packages: if only exact `Achimeld.exe --mcp` processes remain in the current development package, it closes those connectors before building. Any editor, supervisor, worker or other command preserves the save-and-close build guard. Cleanup validates the executable path and process start time against a retained process handle; it does not terminate processes from other packages.

Achimeld implements the original Achiever MCP workflow against its open Rust editor. The original checkout is a behavioral reference, never a build dependency.

## Optional headless connection

Use the visible desktop by default. Only when the user explicitly requests headless operation, use `Achimeld.exe --mcp-headless` to start a windowless supervised project host owned by the MCP connection. Installed configurations use `["--protected", "--mcp-headless"]`; development packages use `["--mcp-headless"]`. No editor window is required. Setup MCP, below Launch Achimeld on the installer finish page, copies an agent prompt and the exact installed desktop configuration, with headless instructions as an explicit alternative.

The headless connector lists and accepts requests only for its own host. An agent may launch the verified `Achimeld.exe` normally (with `--protected` for installed packages) and use the existing `--mcp` connection for visual work. Only one supervised session can own the fixed network broker port at a time. Save and close the current session before launching the other mode, then reopen the project. Sessions do not share unsaved state. Existing storage conflict checks still reject changed files.

Call `list_instances`, then `get_scene`. For a new project, `save_project` accepts an optional unused absolute local-drive `.achv` `path`; omit it on later saves. Existing project and companion files cannot be replaced by this first-save operation. Save before disconnecting: closing the connection terminates its host and unsaved work is lost. `close_editor` rejects dirty headless projects instead of hiding a Save/Discard prompt. Menu tools require the desktop. Steam authentication can still require interaction with the dedicated supervised browser; headless does not mean unattended sign-in.

The following desktop-connection instructions apply to `--mcp` only.

Build a fresh verified package with `build-and-run.bat --offline --build-only`, then open Achimeld normally. Configure an MCP client with the absolute verified package path:

```json
{"mcpServers":{"achimeld":{"command":"C:\\Projects\\AchimeldBuild\\current\\package\\Achimeld.exe","args":["--mcp"]}}}
```

The MCP process verifies and retains locks on its signed package while an editor is available. It exits after two seconds with no editor endpoint, even if the client keeps stdin open or stops reading stdout, releasing the package for rebuilding. This grace also applies when started without an editor and tolerates brief endpoint recreation between requests. With multiple editors, it remains available until the last one closes. Open the desktop before connecting; reconnect the MCP client after reopening the desktop. It does not start the desktop or browser. Run both as the same normal Windows account. Direct startup of `achimeld-app.exe` still requires supervision. Protection applies to the separately launched editor; `--protected --mcp` is unsupported.

The tools include `set_project_settings`, `review_achievement_image_folder`, and `import_achievement_images`. The core tools are `list_instances`, `status`, `get_scene`, `get_node`, `list_icon_styles`, `get_achievement_translations`, `export_achievement_translations`, `import_achievement_translations`, `create_achievement`, `create_stat`, `create_stats`, `update_node`, `move_nodes`, `select_node`, `configure_stat`, `link_achievement_stat`, `add_general_image`, `apply_icon_style`, `export_achievement_icons`, `undo`, and `redo`.

`status` and `get_scene` report modal state. `acknowledge_modal` accepts only the exact `modalId` of an informational OK notice. `list_effect_presets` returns named Explosion Explorer and particle recipes; `apply_effect_preset` applies one saved preset to 1-100 selected achievements in one undo step. `close_effect_explorer` closes that floating editor after its normal save check. Initialization includes a structured `_meta.achimeld` editor snapshot in addition to human-readable instructions.

Steam workflow tools are `get_synchronization`, `validate_steam`, `prepare_synchronization`, `apply_synchronization`, `cancel_synchronization`, `forget_steam_validation`, `delete_browser_profile`, `review_steam_deletion`, and `apply_steam_deletion`. Save the project in the editor or with `save_project` first. `validate_steam` starts the existing supervised connection check. Poll `get_synchronization` until `verified` is true or `error` is set. `prepare_synchronization` then starts a fresh Steam read and prepares a review. Poll until `review` appears. Optional `kind`, `state`, and case-insensitive `query` arguments filter the returned review rows while `totalRows` and `returnedRows` show the full and filtered counts. To apply it, supply its exact `token` and one `{key,action}` choice for every row in the complete review; actions must be listed by that row. The application host checks the review again before sending it to the existing synchronization worker. The call returns when work starts, so poll for completion or failure. `cancel_synchronization` cancels active work or a waiting review. `forget_steam_validation` clears the saved Steam snapshot and downloaded banner in one undoable editor change; save to retain it. Local achievements, stats and synchronization baselines remain. Uploads update the Steamworks draft; publishing remains manual.

`delete_browser_profile` requires `confirmDeletion: true` and an idle Steam operation. It starts deletion of only Achimeld's dedicated Chromium profile through the supervisor. Poll `get_synchronization.browserProfileDeletionActive` and `status` for completion. The project and Steam account remain, but the saved browser sign-in is removed; run `validate_steam` and sign in manually afterward. Preferences > MCP places this command, forgetting validation, and the reviewed Steam deletion commands in the red Sensitive folder. All commands are enabled by default; a folder switch changes every command in that folder, even when the list is filtered.

`open_menu` opens one of the top title menus (`File`, `Edit`, `Tools`, `Windows`, `Help`) and `close_menu` closes the active popup. Both use the selected editor's UI and ordinary mutation revision pins. Nested and context menus remain controlled through their parent UI interactions.

`list_recent_projects` reads the desktop's remembered project paths. `open_recent_project` opens one exact member only when the current document is clean. `open_project` accepts an absolute local-drive `.achv` path without reparse points through the same project loader and clean-document guard. This extends the MCP client's local project file access; the loader still validates format and owned references. `reload_project` reopens the current saved path, resets the project session and discards unsaved editor changes only when passed `discardUnsaved: true`. It avoids closing the editor during recovery. `save_project` writes the existing project path through the normal store, while Save As remains in the desktop. `open_steam_page` opens the pinned App ID's achievements or stats route in the supervised browser; `cancel_steam_read` interrupts that page read. `close_editor` invokes the normal Save, Discard, Cancel close flow.

For draft deletion, call `review_steam_deletion` with exact Achievement or Stat API names. Inspect the returned Steam IDs and names, then call `apply_steam_deletion` with the same targets, review token and `confirmDeletion: true`. The review requires a verified complete Steam snapshot and binds the token to that snapshot and editor session. The existing supervised worker deletes only the reviewed targets, reads Steam again, and saves the verified project. Publishing on Steamworks remains manual. Synchronization performs one reviewed submission at a time; after an import, prepare another review explicitly if more changes are needed.

Preferences > MCP lists every command. All are allowed initially; each can be disabled individually, and Allow all resets the list. The editor enforces this policy for reads, writes, discovery and health. A blocked command returns a permission error.

Use `set_project_settings` with `appId`, `name`, or both to edit the current project in one undo step. Changing the App ID clears validation and the old synchronization baseline, as in the desktop. Save the project afterward. For image batches, `review_achievement_image_folder` lists every supported image directly in one absolute local-drive folder (up to 128 images and 128 MiB) and returns a token. Supply that token and exactly one `{fileName,name,description}` entry for every listed image to `import_achievement_images`. The folder, file metadata, editor session and revision must still match. The host prepares and owns the artwork in the background, then creates the achievements in one undoable edit. Poll status and get_scene for completion. Subfolders and reparse points are not followed.

The MCP facade exits shortly after the last editor closes, including when a client has stopped reading output. Restart the MCP connection after relaunching the editor. Use `reload_project` for a saved-project reset that keeps the current connection alive.

Style authoring additionally provides `list_style_collections`, `get_icon_style`,
`create_style_collection`, `create_icon_style`, `export_style_preview`,
`export_style_collection`, and `import_icon_style`. Follow the
[agent style-authoring guide](agent-style-authoring.md) for the complete workflow,
recipe examples and native 3D cup rendering. Collection creation/cloning stays
outside project history. Explicit import adds one independently identified project
style in one undo step. Collection edits participate in MCP revision pins and retry
caching; they are persisted by collection export, independently of project Save.
App defaults remain read-only opt-in collections in Style Viewer.

Style preview export uses the app's own renderer on a background snapshot and
writes one PNG, default 512 × 512, at most 1024 per dimension. Its destination must
be an unused absolute local-drive `.png` filename. Collection export requires an
unused `.achv` filename and uses the existing owned-artwork/catalog transaction.
Neither tool saves the open project. Both use normal mutation pins; style preview
export has the ordinary 20-second budget. Source projects are not needed at runtime.

The initialize handshake states each open editor in one line: how long that process has been up, the open project name (and its saved path when the project has one), how many achievement nodes it contains, how many of those nodes sync with Steam, and how many stats it has. `list_instances` and `status` return the same snapshot, including a `summary` sentence. `status` takes `processId`. A running editor whose document could not be read still reports process uptime. Achievement nodes include every card on the achievement canvas. The Steam-sync count includes Active and Unsynced achievements and omits Retired cards plus local style and art cards. Stats are counted separately. This read does not save, open, or synchronize the project.

1. Call `list_instances` and choose a `processId`.
2. Call `get_scene` to obtain `projectId`, `revision`, and `result`.
3. Supply that `projectId`, `expectedRevision`, and a fresh GUID `requestId` with each edit.
4. Use the returned revision next, or read again after manual edits. Save through the UI.

Stale state returns `stale_scene`. Active dialogs, inspector drafts, artwork operations or synchronization return `editor_busy`. An identical successful request can be retried with exactly the same arguments and ID. Changed arguments with a cached ID return `request_id_reused`. The last 256 successful responses are cached with a combined 16-MiB cap. Project reopening, restart or eviction ends that guarantee; inspect the scene before issuing new creations. Revisions are local to the editor session and include manual document/navigation changes. Undo/redo share manual history.

Creation accepts English text and integer grid `column`/`row`. Occupied creation positions resolve to the nearest unoccupied grid location; inspect the returned node or scene for the final coordinates. Stat types are `Int`, `Float`, and `AverageRate`. Each edit is one atomic undo step. `create_stats` adds 1-1000 stats in that same single undo step. Pass `stats` as a JSON array or as text. An array entry is an API name, or an object with `apiName`, optional `displayName` (the API name when omitted), optional `type` (default `Int`), optional `column` and `row` together, and optional `minimum`, `maximum`, `defaultValue`, `maximumChange`, `averageRateWindowSeconds`, `incrementOnly`, `aggregated`, and `setBy`. Omitted numbers and flags stay at the new-stat defaults. Text is API names separated by newlines, commas, or semicolons, or one `API name | Display name | Type` line. Lines starting with `#` are comments. The result lists each new node with its final column and row, and the last stat is selected. A duplicate name, invalid entry, or inconsistent range rejects the whole batch before history changes. `move_nodes` accepts 1-1000 unique `{nodeId,column,row}` entries. Node patches preserve omitted values and other languages; description/hidden apply only to achievements. `configure_stat` replaces numeric settings: omitted numbers become null, flags false, and `setBy` defaults to `GameClient`. Link with both `statId` and `unlockValue`, or omit both to unlink. Integer thresholds must be whole numbers within stat bounds; invalidating linked thresholds rejects the edit.

`add_general_image` requires exactly one `imageAssetId`, `atlasId` with optional `tileIndex`, or absolute local-drive `filePath`. Files are decoded off the UI thread and copied into the Art Data Bank. Identical owned bytes reuse a project asset. Returned `generalImageId` indices correspond to style layers' `generalImageIndex`. Styles include project entries and saved global templates. Applying a global style retains it in the project in the same undo step; layer/effect IDs are independently cloned and folder/mask links remapped. Required general images must already be attached.

Icon export accepts an existing absolute local-drive `destinationDirectory`, optional `format` (`Png`, `Jpeg`, `Bmp`, `Tiff`), and width/height 1–4096 (default 256). Color and fully grayscale `_gray` pairs use sanitized API names. JPEG flattens alpha onto black. Matching image files are replaced. Pair collisions and excessive result inventories reject before writes. Per-achievement failures are returned; interruption can leave earlier complete files. Background export uses a pinned snapshot without changing project settings/history.

For localization, call `get_achievement_translations` with `processId` to receive `result.csv`, a suggested filename, language metadata and row count. It returns two rows per achievement: display name and description, with stable `ID`, API/field `Context`, English source templates and the supported language columns. Keep ID, Context, English and column headers unchanged, and retain `{0}` placeholders in translations. To create a handoff file, call `export_achievement_translations` with an absolute local-drive `destinationFilePath` ending in `.csv` and the usual mutation pins. Export requires an unused filename, writes UTF-8 with a BOM, and rejects the reserved `.achimeld.localization.csv` suffix.

Return translated content through `import_achievement_translations`, supplying exactly one of `csv` or absolute local-drive `filePath`, plus the current project/revision/request identity. File operations reject UNC/device paths and reparse points. Inline CSV is limited to 2 MiB of UTF-8; use file export/import for larger catalogs (up to 64 MiB). Rows can be reordered or omitted. Blank cells preserve current translations. Unknown/duplicate/shared IDs, changed English/context, malformed CSV and broken placeholders reject the complete import. Preparation runs in the background and rechecks the editor session, revision, busy state and cancellation before one undoable edit. The result reports `changedCells`; use `save_project` or desktop Save to persist the project/catalog pair. The project-owned companion CSV should not be edited directly. See [translation boundary contracts](security/contracts.md#achievement-translation-handoff).

Stdout contains only newline-delimited JSON-RPC; diagnostics use stderr. Protocol versions 2024-11-05, 2025-03-26, 2025-06-18 and 2025-11-25 are supported. The initialize result advertises the embedded orange application mark in `serverInfo.icons` as one 256 by 256 PNG data URI. No remote image is fetched. Lines/pipe frames are capped at 16 MiB and nesting at 64. The stdio queue holds eight messages and the editor queue one. Overload closes the connection. Operations have a 20-second response budget, including translation CSV work; icon exports have ten minutes. Cancellation notifications/stdin closure interrupt a waiting facade. Disconnect/expiry cancels queued work; edits already executing complete atomically. Decode/filter primitives are not preemptible. Inspect or retry identically after uncertain completion.

The local pipe name includes the current Windows account hash and editor PID. A first-instance, non-inheritable ACL allows that account and SYSTEM; remote clients are rejected. The facade verifies the kernel-reported server PID. One connection carries a request, response and client acknowledgment before server handle closure. Connected local clients are trusted to edit the open project. This is not protection against compromised same-user processes. The registry has no executable/URL dispatch or unsupervised browser launch. Project open and Save use the existing guarded editor storage path; deletion uses the existing reviewed Steam worker path. Steam changes use the existing supervised review and synchronization worker.

The implementation follows the official [stdio transport](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports), [lifecycle](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle), and [tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools) contracts. Run `build/Audit.ps1 -Offline -Fixtures` and inspect its exact source evidence; see the [MCP audit](security/mcp-audit.md) for scope and limits.
