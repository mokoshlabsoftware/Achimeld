# Rust desktop rewrite

Updated 2026-10-15. The Achiever checkout was consulted as a behavioral reference. It is never a build input. The authored translation catalog is copied into this repository; no C# UI code or prebuilt application assembly is used.

## Implemented local workflows

The [upper-bar contract](upper-application-bar.md) defines the two top rows, hover switching between open File/Edit/Tools/Help menus, and left-aligned menu commands. Style Viewer is a main canvas mode beside Art Data Bank, with larger style banners, right-click rename, a miniature bank for any project image or atlas tile, and a project-saved unlock value defaulting to 10. It retains portable style sets and manually entered style-to-Steam Achievement Set links. The viewer owns its own document, artwork and render cache; preview inputs are saved as project metadata without modifying canvas achievements.

The Achievements and Stats top bars include **Sort**, opening the original Achiever
node-grid panel: independent 1–10 items per row/column, ID or icon-style ordering,
new line per style, rows/columns, all/selected items, stat activation, and **Align**.
Achievements group by matched style name and recipe before linked-stat identity,
threshold, internal ID and display order; Stats retain display order. Style matching
uses the native editor's shared identity-independent recipe signature and its project
and user style libraries. Selected-only alignment skips whole stationary card
rectangles, including off-grid and automatic positions; an empty selection does
nothing. Align moves positions without changing IDs or record order and uses one
shared undo step. Settings persist through the host-owned preference store. The
reference is `GridSettingsWindow.xaml` and `AlignProjectNodesEdit` in Achiever's
`ViewModels/EditorViewModels.cs`; neither is a build dependency. Generated icon
sources, exact prompts and embedded pixels are retained under the UI toolbar assets.
Focused application and pointer-driven UI checks cover both canvases. Set
`ACHIMELD_SCREENSHOT_SORT` to `achievements` or `stats` and select
`native_sort_screenshot` for a native preview under the external current build
directory; `ACHIMELD_SCREENSHOT_SORT_OPTIONS` previews selected toggle states.

Art Data Bank is an upper view and Tools menu entry with Images and Atlases tabs. File drops (up to 32 files), ordinary imports and layer imports all retain owned lossless PNG snapshots, including in unsaved projects. One background artwork job decodes/resizes at a time, publishing a 64-pixel preliminary image before high-quality resizing and encoding; storage inventory runs separately and lists render only visible rows. Project switches cancel obsolete artwork work at decoding/filter boundaries. Imports have a 64 MiB encoded-file limit and 128 MiB decoded RGBA limit. Resize/reload keep asset IDs and commit through project history; previous immutable versions support undo. Reload uses the standard Windows file picker to choose a replacement source. Refresh updates previews and disk inventory. The bank displays dimensions, per-asset file sizes, deduplicated referenced bytes and saved-bank disk use including older versions.

The bank details pane uses the Panel palette color and a visible horizontal-resize grip. Wide windows retain the chosen pane width across tabs; narrow windows stack the independently scrollable panes. New file imports record optional `importSource` metadata (`kind: File`, absolute original `path`); clipboard imports record `kind: Clipboard`. The default atlas uses `assets.atlasImportSource`. The source label wraps and can be selected for copying. Resize preserves this metadata, reload replaces it, and history/save/load retain it. Older assets without provenance display “Source not recorded”. A recorded local file seeds the user-requested native reload picker; it does not authorize automatic reading or replace the owned image reference.

Saving copies available schema-defined image references into a sibling `<project>.art-data-bank` folder using content-addressed filenames and project-relative references. Save As creates its own copies. The JSON/localization recovery pair is unchanged: immutable art files publish first, so a failed save can leave unreferenced artwork but cannot publish JSON pointing to an unstaged new file. Existing hash-named files with different bytes are preserved and reject the save. Opaque metadata is not rewritten. Legacy unavailable references remain repairable; move the project, CSV and bank folder together. Unsaved imports use a host-owned temporary staging folder until saved; staging is not crash recovery. Retained versions are not automatically pruned.

Achievement/layer previews treat missing or undecodable image layers and out-of-range atlas tiles as transparent, preserving the remaining composition. A missing mask stays transparent rather than revealing masked content. Structural, cancellation and render-budget errors still fail. Export remains strict and reports unavailable artwork instead of publishing incomplete icons. Native layout previews and deterministic portability, content-collision, source-deletion, resize/reload undo and missing-layer fixtures exercise these paths; they do not qualify hostile same-user filesystem races or installed runtime enforcement.

The native window has Working and Steam views, achievement and stat cards, filtering, selection, grid dragging, zoom/pan, property and localization inspectors, project settings and Preferences. Colors come from Preferences → Colors, with interaction colors derived from the named palette. Color, size and spacing changes preview live; Cancel restores the saved appearance. The naming convention generates new achievement API names.

The project style dropdown shows image banners three times the collapsed image strip's height, with adjacent Rename and Delete actions. Rename opens the application prompt format with a complete, aspect-preserving default icon preview, a name field, and Approve/Cancel; approval changes only the name in one undo step. The selected banner's small subtitle displays its local Steam achievement set links, or “Not tied to any set.” These labels describe saved/open style-set metadata, not live Steam qualification. The original `IconStyleLibraryStore` and `IconStyleExplorerButton` were checked as behavior references: `user.icon-styles.json` can include base64 `PreviewPng` images. Migration/import preserves those default images, and matching previews dropped by earlier migrations can be recovered without replacing Rust names or recipes. Host background workers decode bounded PNGs or render a recipe fallback, share the existing cache/queue limits, and publish small previews before refinement.

On both node canvases, dragging the left mouse button from empty space draws an
Accent selection rectangle and selects intersecting, filtered cards as the pointer
moves. Ctrl retains the previous selection; icon editing also retains its current
selection. Ctrl-click toggles individual cards, including achievement artwork.
Dragging any selected card previews the entire group with its spacing intact and
commits one grid-snapped undo step on release, including outside the canvas.
Dragging an unselected card selects and moves that card. Escape cancels movement
or restores the selection from before a rectangle gesture. Middle/right dragging
continues to pan. Pointer regressions cover both canvases, zoom, reversal, filtering,
disabled/covered areas, artwork hits, cancellation, and grouped undo/redo. The
reference is `Views/WorkingView.xaml.cs` in the original Achiever checkout, read
only as behavioral evidence. `native_group_selection_screenshot` captures the
rectangle preview using `ACHIMELD_SCREENSHOT_TO`; set `ACHIMELD_SCREENSHOT_STATS`
for the Stats canvas.

In Achievements and Stats, the arrow keys select spatial neighbours within a
90-degree cone centred on the requested direction. Selection balances proximity
with alignment by scoring squared forward distance plus four times squared
sideways distance; equal scores prefer closer alignment, then a stable node ID.
The first selected, filter-matching node is the anchor, and already selected nodes
are skipped. Navigation stops at a dead end. With no matching selection, an arrow
selects the node nearest the visible canvas centre. Filtered nodes are excluded;
off-screen matches remain reachable and are revealed immediately with the smallest
necessary pan at the current zoom. Selection alone adds no undo step; revealing a
node uses the existing camera command. Key repeats and event order are retained.
Focused controls, menus, dialogs, invalid edit drafts, pointer gestures and inactive
or disabled canvases retain ownership of their input.

About opens modally on the first launch and can be reopened through Help → About. Dismissal sends the fixed local `AboutDismissed` intent; the host atomically saves a bounded acknowledgement in `%APPDATA%/Achimeld/rust-about-seen.json`. This application state is separate from appearance preferences and project undo, so changing projects, resetting colors or undoing an edit does not re-enable the first-launch dialog. The About text describes local editing and reviewed Steam import/draft-upload capabilities.

All durable local document edits pass through the application command owner. Transactions validate on copies before committing and share one undo/redo history, including deletions and dependent links, duplication, translations, asset imports, properties, recipes, settings, preferences and layer reorders. Duplication keeps translations and remaps recipe identities. Invalid edits stay visible as drafts, block saving/closing, and can be reverted. Undo first discards an invalid draft. History stores reversible field/array/catalog changes, retaining at most 128 entries with a 64 MiB serialized-payload budget; that is not a measurement of total process memory. Focus changes finish property-edit gestures. Saving establishes a content checkpoint, so undoing back to it clears the dirty indication. Settings reject stale application after another project edit.

Layer dragging uses stable layer IDs and the original row geometry throughout a gesture, with a midpoint dead band. It paints an insertion marker without rearranging hit targets or rendering a speculative recipe. A drop commits one named reorder. The background renderer accepts only the newest requested generation and retains the last successful preview through queued work and failures; failed updates show an explanation.

Achievement previews first render with a maximum edge of 64 pixels, retaining the configured aspect ratio, then refine to the configured output resolution. A pool of one to four background threads prioritizes initial work and waits for in-flight initial renders before taking refinement work. Refinement is admitted after the UI polls the initial pixels. Source decoding is serialized through a shared 128 MiB cache to avoid duplicate atlas decodes; composition runs concurrently outside that lock. Preview pixels are immutable shared allocations, so normal repainting does not copy them. The preview renderer produces only the displayed achieved variant; paired PNG export still uses the same composition and derives its unachieved variant.

Achievement, layer and asset previews use GPU textures with linear magnification/minification and linear filtering between GPU-generated mipmaps. Refinement updates the existing texture; zooming reuses its mip chain. CPU preview and GPU texture caches each retain at most 512 entries and 128 MiB of pixel content (the texture budget includes mip levels). Each initial/refinement queue holds at most 512 jobs; the result channel holds at most one result per worker. These are cache/queue limits, not a whole-process RSS bound. Cancellation does not preempt an individual decoding/raster/filter primitive.

The reference `GpuPreviewImage` and `EditorViewModels` progressive pass were inspected as behavioral evidence only. The pinned egui Glow backend implements [linear mipmap filtering and GPU generation](https://docs.rs/egui_glow/latest/src/egui_glow/painter.rs.html); egui documents [mipmap options and backend support](https://docs.rs/epaint/latest/epaint/textures/struct.TextureOptions.html). Pool sizing reads Rust's [available parallelism estimate](https://doc.rust-lang.org/std/thread/fn.available_parallelism.html) once at startup, leaves one CPU available when possible, and caps rendering at four workers.

Local release measurements on 2026-10-14 used 80 synthetic gradient/shape/blur recipes, with a 1 ms polling interval. One worker: first polled preview 1.79 ms, all initial previews 185.74 ms, all 512×512 outputs 3.54 s. Four workers: first polled preview 2.25 ms, all initial previews 35.64 ms, all 512×512 outputs 917.65 ms. The previous serial paired 256×256 rendering took 11.63 ms for its first icon and 887.94 ms for all 80. These measure availability of rendered pixels, not cold file decoding, GPU upload/presentation or the user's project. Reproduce with `build/Rust.ps1 -CargoArguments @('test','--release','-p','achimeld-app','--bin','achimeld-app','--locked','--offline','progressive_preview_timings','--','--ignored','--nocapture','--test-threads=1')`.

Focused regressions exercise the quick-pass barrier, UI consumption before refinement, shared preview pixels, cross-project generation reuse, cancellation with a full result channel, export/preview pixel agreement and stable texture identity with mipmap options. The native desktop screenshot fixture was run and inspected at `.artifacts/mipmapped-desktop.png`. The application/UI/imaging regressions pass with normal Windows access; restricted-environment hard-link export publication initially failed and is not evidence of a rendering regression. Native fixtures unrelated to this change and authentic legacy-project/settings fixtures were not selected in this run. This work does not replace the separate full security audit evidence.

The Icon tab's Show layers panel button reopens and recenters it. Legacy layout settings retain their serialized shape, with positions now interpreted in application coordinates. The editor has a draggable divider, a top-to-bottom layer stack, rendered layer and mask thumbnails, folder expansion, visibility, opacity/blending, effects, add/move/delete tools, recipe and layer copy/paste, subtree cloning, grouping, and transform/shape-transform copy/paste. Delete/Ctrl+D/Ctrl+C/Ctrl+V act on layers when the layer editor has focus. Layer deletion preserves the achievement and clears dependent mask links.

The property pane includes color swatches, source selectors, visual image/atlas picking, folder masks, adjustment sliders, selective-color ranges, a draggable RGB curves graph with an input histogram, gradient stops/channel mapping and effect parameters. Disk import can add or replace a layer or create a folder mask; the image library and recipe update in one command. Icon layers resolve only the current project's `iconStyles` library (up to 128 validated recipes), stored in the project JSON. The style banner saves/deletes project styles and offers a separate global-template import menu; importing creates a project copy with its own identity without applying it or modifying the global template. Affect style edits the project recipe and matching icons in one undoable transaction. Undo/redo restores both the recipe and icons; style creation, import and deletion also participate in project dirty state and history. Older projects without `iconStyles` recover up to 128 repeated explicit recipes using identity-independent signatures, with stable generated identities/names and no changes to the icons. Palette rendering never normalizes sparse stored recipes.

Images can be imported into the project library and chosen by image or atlas layers. The renderer supports solid/linear/radial gradients, basic rectangle/sphere/polygon/star shapes, text with common Windows font families and alignment, image/atlas/general-image layers, folders and masks, curves, contrast, hue/saturation, basic selective-color controls, gradient mapping, unsharp mask and basic color/outline/shadow/inner-light/box-blur effects. Recipe copy/paste preserves links while assigning fresh IDs. Preview and PNG export use the same renderer; unachieved exports use the configured grayscale/tint and opacity. Export stages all files before publication, refuses filename collisions and existing outputs, runs in the background and supports cancellation. Publication rollback is exercised by a cancellation fixture; crash recovery for external exports is not implemented.

Project/catalog loading is bounded and SHA-256 pinned for schema 1. Saves stage both members and originals, publish a recovery record, then replace both files and record completion. Interrupted recovery validates both members before rollback; corrupted or externally changed members are preserved for resolution. Save As rebases image references and refuses existing destinations. Unexposed JSON fields survive edits and saves. This implements application-level recovery, not a filesystem-wide transaction or a guarantee against every power/storage failure.

Open/Save, image import, translation import/export, export-folder and settings-folder selection use standard Windows dialogs owned by the application window. Cancel and Escape preserve the current project and undo history; cancelling Save before Open/New/Exit stops the pending action. Save As still requires unused project and localization filenames, and the existing store remains the final validation boundary. Regression fixtures cover cancellation, failed saving, pending-request exclusion, picker validation and disabled keyboard shortcuts. Interactive Windows acceptance remains a separate check.

Steam reads remain an explicit supervised, read-only operation with manual sign-in. Results are pinned to the project identity/App ID that initiated the read. Cancel read terminates the operation. The separate reviewed synchronization protocol retains project/remote pins, consumes selected steps once and journals uncertain results; browser launch recipes are unchanged.

## Boundary and tests

The gradient editor restores the original Achiever visual strip, draggable color stops, click-to-edit color picker, and right-click create/change/delete actions. New stops sample the current ramp, including alpha; deletion protects the final stop. The selected stop has compact position and swatch controls and a shared fixed-height action bar. The editor is shared by gradient layers, gradient overlays/effects, and vignette maps, without changing recipe fields or host I/O. Color encodings stay internal. Opening sparse recipes leaves their stored data untouched; dragging uses the existing grouped undo transaction.

SDF vignette properties include inversion and a Color / Gradient map fill selector. Gradient stops follow the fade from transparent to full strength and retain their alpha. Inversion moves the fill to the center. Solid color and gradient settings survive fill switches and project saves; existing vignettes keep their rendering and synchronization fingerprints until edited. Gradient presets and stop controls are shared with the existing gradient editor. The signed distance determines placement, so the map has no spatial angle or gradient-kind fields.

Dropdowns, nested menus, and context menus use square, borderless panels with no outer padding or gaps between their square buttons. Title-bar menu buttons also touch without gaps. Other application controls retain their configured corner radius and spacing.

Application buttons, icons, title menus and toolbar tabs share three borderless styles (Standard, Accent and Quiet). Hover exchanges each button's body and text colors, with reversible eased progress at 0.15 seconds for the body and 0.2 seconds for text/icons. A curved intermediate text color path avoids identical RGB midpoints; arbitrary user palette colors are not a guarantee of readable contrast. Keyboard focus uses the same filled state, and disabled buttons do not animate. Preferences > App style previews the styles, selection, disabled controls, icons and menus with live palette/font/radius settings.

UI text uses the installed Windows Segoe UI regular and bold faces, with bundled fallback fonts. Embedded Noto Sans CJK 2.004 regular, bold and Mono faces cover Korean, Simplified Chinese, Traditional Chinese and Japanese without system language packs. The interface language selects regional Han forms; all four scripts remain available in mixed-language project text. Collection bytes are shared, and unchanged language settings do not rebuild fonts. The [font provenance and license](../crates/achimeld-ui/assets/fonts/README.md) and both collections are retained in packaged source inventories. Both axes use font hinting and glyphs align to the physical pixel grid instead of fractional glyph bins. Hover/focus animates text color while retaining the resting font weight and text cell. Bounds and filled hover states are exercised at 100%, 125%, 150% and 200% display scales. The host supplies installed font bytes; presentation performs no filesystem reads. Text-layer artwork continues to use the separate host-owned system-font renderer.

Legacy canvas positions retain their original 20-DIP grid meaning. Achievement cards use the reference 336×118 dimensions and stats use 236×178, with matching automatic placement and duplicate offsets. Achievement/stat cameras restore independently; navigation records the schema camera fields through validated commands. “Fit all” frames the complete canvas without rewriting node positions. Regression coverage includes saved camera restoration, grid spacing, and a separately selected real-project fixture with 100 achievements and 32 stats, checking every entity, localization row, recipe, link and camera through Save As/reload. Exact reference pixel rendering remains unqualified.

Middle-button and right-button drags pan the camera across empty canvas, cards and artwork, including in Icon mode. The gesture follows pauses, reversals and release outside the canvas, and remains one undoable camera change. Drags starting over the inspector, Layers panel or a disabled canvas do not pan it.

Preferences → General exposes the Achimeld folder picker; a first run without a saved folder offers the same picker. The host reads the original HKCU Achimeld/Achiever `SettingsFolder` value when no Rust locator exists, then keeps the explicit Rust choice in `%APPDATA%/Achimeld/rust-settings-folder.json`. Preferences, gradients, global icon templates and editor/navigation state use the selected folder; project icon styles stay with the document. Original PascalCase preferences and domain-style numeric enums/wrapped IDs are translated on read. Migrated Rust settings use separate filenames and preserve original preset files. Gradient layers and gradient-overlay effects can choose/save shared presets. Changing to an empty folder carries the current library; invalid destination libraries prevent activation.

Project localization is a project-owned companion CSV. Shared settings never override its path or bypass the schema-1 hash. Save/Save As writes `<project>.achimeld.localization.csv` beside the `.achv`, records a relative reference and commits the pair through existing recovery. Missing catalogs report the expected path and preserve the current document. Copying a project between folders requires its matching CSV as well.

For translation handoff, use **Tools → Export achievement translations…**, or **Export CSV…** in an achievement's Localization inspector. Choose a separate, unused `.csv` filename. The UTF-8 comma-separated copy contains two rows per achievement (display name and description), stable `ID`, API-name/field `Context`, English source templates, and the supported Polish, Simplified Chinese, Traditional Chinese, Japanese, Korean and French columns. Existing translations are included without English fallback. Keep column headers, ID, Context and English unchanged, and retain any `{0}` placeholders in translated cells. Reordered rows and subsets are accepted; blank cells leave current translations unchanged.

Use **Import achievement translations…** (or **Import CSV…**) to bring the returned file into the open project, then Save. Imports validate every row before one undoable edit; changed source/context, unknown or duplicate IDs, malformed CSV and broken placeholders reject the entire import. Parsing and export I/O run in one bounded background job; edits made while reading cause the import to be discarded with a retry message. Exports publish complete files without overwriting existing destinations, and reject the project companion's reserved filename suffix. Do not translate the project-owned `.achimeld.localization.csv` directly: its hash belongs to the paired project save.

The local MCP editor server exposes `get_achievement_translations` (CSV content, source project/revision and language metadata), `export_achievement_translations` (absolute unused `.csv` destination), and `import_achievement_translations` (exactly one of CSV content or an absolute CSV file path). Inline content is limited to 2 MiB to keep nested JSON responses inside the 16 MiB transport budget; files retain the 64 MiB catalog limit. Exports and imports use the same CSV routines as the desktop and run on the existing bounded editor worker. Mutating calls require the current `projectId`, `expectedRevision` and a fresh `requestId`; successful identical retries use the existing result cache. An import rechecks revision/session, cancellation and editor-busy state immediately before committing. Imports update the open document in one undo step and require a desktop Save to persist the project pair. Ambiguous localization IDs shared between fields or with stats are rejected.

File → Open Recent shows up to ten full project paths, newest first, with a localized disabled placeholder when empty. Successful Open, Save and Save As update the list, deduplicating Windows paths without ASCII case sensitivity. The host atomically persists bounded navigation state in `%APPDATA%/Achimeld/rust-recent-projects.json`, separately from project undo and appearance preferences. Test hosts use unique settings folders under the external test output directory. User history excludes generated test projects and filters entries left by older test runs, while retaining ordinary missing projects. Recent selection uses the ordinary invalid-draft and unsaved-change gates and normal project/catalog validation; its chosen path remains pinned while a preceding save reorders the list. Failed loads preserve the current document/history. A history-write failure reports a warning after a successful open/save. Interactive Windows menu acceptance remains a separate check.

`achimeld-ui` depends only on presentation/data/application crates. It receives read-only state, validated commands and a closed set of user intents. The app host owns dialogs, storage, preferences, rendering jobs, export and the typed reader. Application/imaging/UI code forbids unsafe code. `build/Test-DesktopBoundaries.ps1` guards the production dependency set and direct host-I/O imports; test-only native screenshots use eframe separately.

This is a source architecture boundary within one supervised process. It does not isolate malicious machine code executing in that process. The [threat model](security/threat-model.md) and [known gaps](security/known-gaps.md) still apply. Browser/worker authority remains behind the existing authenticated process/protocol boundary, with installed enforcement and live Steam qualification separate from source fixtures.

### Icon and canvas reference corrections

Text-layer Font family uses a searchable, sorted Windows system-font picker. The host discovers installed outline families once on a background thread and supplies only names to the UI. Rendering resolves the selected face through Windows rather than an eight-family filename table; collection faces are loaded through their own font tables. Missing saved family names remain intact until a replacement is selected, and unknown names never silently substitute another face. Segoe UI retains the reference semibold rendering. Font reads retain the 32 MiB limit, and the host font cache is capped at 64 MiB. No recipe/wire fields or worker capabilities change; fonts remain local system resources and are not bundled with saved projects.

Font-picker verification on 2026-10-16: three host tests passed, including loading/parsing all 263 offered system faces, rejecting unavailable names, and rendering distinct Cambria collection faces. Three final picker interaction/layout checks passed through an isolated source harness, and the native searchable dropdown screenshot was inspected. The standard UI test build could not replace a test executable held by another native fixture; an alternate UI build then encountered concurrent, unfinished Perlin-layer inputs. The isolated checks use the actual picker, shared buttons, typography and theme sources. An earlier strict workspace Clippy run passed; the final repeat was blocked by the concurrent Perlin control referring to a missing `LayerAction::AddPerlinMask` variant. Full audit fixtures and packaged/installed desktop acceptance were not selected.

Shape rotation now acts on the sized shape in canvas coordinates, including legacy numeric shape kinds. Vector shape edges are antialiased; layer rotation uses pixel centers and premultiplied bilinear sampling. Positive contrast uses the legacy reciprocal curve. Icon text has the reference edge padding, multiline alignment and vector outlines; Segoe UI icon text uses the reference semibold face. Saved text outlines and effect outlines honor inward, centered and outward placement. Raster outlines split odd widths between outside and inside, preserve translucent artwork and support square/round footprints. Inner light honors offsets, cutout, its independent blur color/opacity/blend mode, and the artwork footprint before outlines; protected outlines survive subsequent lighting and blur.

Achievement labels fade over 0.4 seconds at 50% zoom and below, and the overview icon expands into the card height. Stat-linked cards have a palette-derived staggered arrow wallpaper and subtle corner glow. The layer focus overlay connects visible edited icons to the current Layers header thumbnail, with the header portion painted beneath its controls. It uses the same style membership as editing, recomputes CPU line geometry after the floating window is placed each frame, and schedules no image rendering for dragging or zooming the panel. Offscreen/filtered icons are omitted. The full header background, including margins and subtitle, moves the panel; its thumbnail, style menu, recipe actions and close button retain their own interactions. Header labels do not intercept dragging for text selection.
