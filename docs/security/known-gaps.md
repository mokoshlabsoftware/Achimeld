# Known qualification gaps

These gaps must remain visible in audit reports and package acceptance. They are not represented as passing tests or silently waived.

| Gap | Scope / next evidence |
| --- | --- |
| Default user-session isolation | No administrator installation or WFP policy is required. Authenticated status reports `networkEnforced=false`; package verification/locks, Jobs, IPC, broker attribution and browser request policy remain active. Application rules do not contain direct sockets or compromised runtime code. Use explicit `--protected` for administrator-owned installation and Windows socket denial; that scope still requires separate acceptance. |
| Full installed WFP/browser acceptance and live Steam read | Historical status remains incomplete. New source/receiver changes require a fresh signed candidate, protected administrator installation and normal-user acceptance for that exact manifest, then a separately scoped live read. |
| Live request-policy compatibility and browser startup | Login families, static-resource prefixes/types and image locations are deliberately closed. Synthetic fixtures exercise routing/denial, not the live site's complete dependencies. Unrecognized requests stop the session; add exceptions only from reviewed, redacted live evidence. Offline context initialization does not establish OS containment of earliest Chromium startup/internal traffic. |
| Pinned Playwright intercepted-WebSocket teardown | The 1.62.0 .NET SDK throws on missing close-event fields during graceful context teardown after WebSocket interception. Requests never connect to a server; policy rejection is terminal and the worker monitor exits its process/Job. The fixture verifies this terminal path. Graceful socket teardown is not qualified; assess an upstream fix separately rather than suppressing the exception. |
| Third-party runtime supply chain | All application Browser/Core/Security code is local and compiled here. NuGet content hashes pin Playwright/Node; bridge build properties pin the .NET version; Chromium is archive-digest pinned. Independent reproduction, runtime advisory assessment, and upstream browser/Node source review remain separate. |
| Independent release identity | The development installer now requires a separately retained trusted-build verifier SHA-256 and runs the matched bytes only from administrator-only staging. Obtaining that digest from the supplied untrusted package defeats the check. Official publisher identity, authenticated distribution and reproducible builds remain unimplemented. |
| General process/filesystem isolation | Jobs/WFP/current-user ACLs do not defeat same-user injection, administrator/kernel compromise or arbitrary execution inside a supervised process. Read-only enforcement applies to the receiving protocol; malicious app code could attempt alternate packaged runtime launches. Containing that code execution requires a separate isolation/authority design and qualification. |
| Long-running fuzz campaigns and platform concurrency qualification | Seeded/bounded mutation and negative regressions exercise parsers; they do not replace sustained coverage-guided fuzzing, resource measurements or platform stress/OS-version qualification. |
| Reviewed draft synchronization and storage qualification | Reviewed import/upload is implemented with synthetic receiver/portal evidence. Live selectors, image conversion tolerance and account-dependent saves have not been qualified for this package. Steam has no atomic compare-and-save; the check/save race remains. A failed step is never replayed; the host journal requires a fresh plan. Journal disk failure and local paired-save recovery do not qualify every Windows power-loss/concurrency scenario. Publication and remote deletion remain unavailable. |
| Steam Achievement Sets compatibility | The current flat configuration normalizer, project/snapshot models, fingerprints and legacy draft writer do not support sets or archive metadata. New editor requests and controls require redacted authenticated fixtures before adapter changes; a successful legacy fixture audit does not qualify this beta. See the [compatibility review and migration requirements](../steamworks-migration.md#achievement-sets-compatibility-review). |
| Local editor MCP | Open-editor operations use a current-account Windows pipe, bounded requests, session/revision guards and shared undo. Local stdio/pipe fixtures are separate from installed-package, different-account ACL and external-client acceptance. Retry records expire after 256 responses/16 MiB, project reopening or restart. Cancellation is best effort before an atomic edit begins. Explicit icon export overwrites matching image files and may leave earlier complete files on interruption. Same-user hostile filesystem races and total CPU/RSS remain unqualified. MCP exposes no Steam writes, project save/open, deletion or individual layer editing. |
| Desktop and imaging parity | The native Rust UI is implemented in part. The [parity ledger](../desktop-rewrite.md) lists remaining workflows, rendering differences, language/font coverage and new dependency review. The UI/application boundary is inside one supervised process and is not a separate security sandbox. |
| Dependency advisory freshness and third-party runtime advisories | Rust advisory scans are separately selected and timestamped. The public-verification-only RSA use has an [expiring exception](dependency-exceptions.json) for [RUSTSEC-2023-0071](https://rustsec.org/advisories/RUSTSEC-2023-0071.html), which concerns private-key timing and currently has no patched version. This does not cover private-key operations. Yanked registry checks and third-party runtime advisories require separate assessment. |
| Independent audit/CI attestation | Local self-review and evidence are not an independent third-party audit. The Windows CI definition needs an actual configured runner and preserved evidence. |

No blanket bootstrapper lint exclusion remains. If a new exception becomes necessary, record its exact lint/location, reason, remediation, responsible maintainer and review expiry here, and include it in the audit scope.
